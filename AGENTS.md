# AGENTS.md

Guidance for coding agents working on `locguard`.

## Purpose

`locguard` is a fast, zero-config Rust CLI that enforces a maximum physical line count for authored source files. Keep the implementation simple and byte-oriented: the product is a file-size invariant checker, not a semantic code-metrics framework.

## Architecture

- `src/main.rs`: process exit boundary only.
- `src/lib.rs`: clap/error boundary.
- `src/app.rs`: scan orchestration.
- `src/cli.rs`: public command/flag model and help text.
- `src/config.rs`: `.agents/.locguard.toml` parsing and defaults.
- `src/discovery.rs`: Git-aware and filesystem candidate discovery.
- `src/policy.rs`: source recognition, built-in exclusions, globs, exemptions, overrides.
- `src/scanner.rs`: parallel byte-level physical-line threshold scanner.
- `src/output.rs`: deterministic human/JSON diagnostics and exit-facing report.
- `src/init.rs`: optional config creation.
- `tests/cli.rs`: end-to-end behavior across temporary Git repositories.
- `dist-workspace.toml`: native/npm release configuration.
- `docs/`: self-contained Astro/ZueDocs workspace.
- `.agents/skills/release/SKILL.md`: canonical release procedure.

## Product invariants

- Zero configuration is the normal experience. Never make `locguard init` required.
- Default hard limit: 1,000 physical lines; default warning threshold: 90%.
- Comments and blank lines count. Final unterminated lines count.
- Bare `locguard` checks current Git changes; `locguard scan` checks the whole eligible tree.
- Git-ignored, generated, vendored, dependency, cache, and build-output files are skipped by default.
- `--file` is exact intent; `--dir` scopes normal source recognition.
- Permanent exact legacy exceptions live in `[exempt].files`.
- CLI policy overrides config; config overrides built-ins.
- Violating files should stop being read once the threshold is proven unless `--exact` is requested.
- Do not add AST parsing, logical LOC, comment stripping, persistent caches, or language-specific semantic complexity without an explicit product decision.
- Do not follow symlinks or recurse submodules.
- Keep source files comfortably below locguard's own 1,000-line default.

## Commands

Fast Rust loop:

```bash
just check-fast
```

Full Rust validation:

```bash
just check
```

Useful focused checks:

```bash
cargo fmt --all -- --check
cargo check --locked
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo test --locked --test cli
cargo run -- --help
cargo run -- scan
```

Docs, run serially:

```bash
just docs-test
just docs-check
just docs-build
```

Release configuration:

```bash
dist plan
dist generate
```

## Coding conventions

- Rust 2024 with the exact toolchain in `rust-toolchain.toml`.
- `unsafe_code` is forbidden; `dbg!`, `todo!`, and `unimplemented!` are denied.
- Keep `main.rs` tiny and behavior testable through library modules.
- Prefer measured reductions in files/syscalls/bytes over micro-optimizations.
- Preserve stable exit codes: 0 pass, 1 policy violation, 2 usage/config/filesystem/tool error.
- Keep human output compact and deterministic; JSON must never fabricate an exact line count after an early exit.
- Unknown config keys must stay errors so typos cannot silently weaken policy.

## Docs boundary

All web tooling stays under `docs/`. Vercel uses `docs` as Root Directory and `docs/scripts/should-build.mjs` skips Rust-only production rebuilds.

## Release boundary

`dist-workspace.toml` is maintained source. `.github/workflows/release.yml` is generated by the pinned `dist` version and must not be hand-edited. For any release request, read `.agents/skills/release/SKILL.md` first.
